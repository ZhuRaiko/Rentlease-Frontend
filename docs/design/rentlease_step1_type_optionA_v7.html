  • ①The footer asks for the type before anything else.
  • ②For an unsupported type the footer shows no range count, because there is no range to count.
  • AThe supported list is exactly what the estimator accepts: apartment, house, condominium (rentalEstimateEligibility). The city also has to be one the estimator covers: Imus, Dasmariñas or Tagaytay. Do not hard-code a second list in the UI; read the shared eligibility.
  • BChanging the type after filling the form keeps shared fields (bedrooms, bathrooms, furnishing, amenities, floor area) and hides the range-only ones (subtype, unit floor, lot area, parking). Hidden values are kept until the person saves, so switching back loses nothing.
  • CStudio. “Studio” exists today as a top-level type and also as an apartment subtype. A studio apartment gets a range and a “Studio” room type does not, which is confusing. My suggestion: keep “Studio” as an apartment subtype only and remove it from the unsupported list. It is your call.

Why this layout

  • Good: smallest change, every type one tap away, easiest to build.
  • Weak: the page is long on arrival, and the split is only a label.
