Rules for Claude Code

RuleDetail
Consent logicDo not change ShareWish.ts or LocationShare.ts. The one button calls the existing confirm-and-share action when the switch is on and the confirm-without-sharing action when it is off.
Switch defaultOff. See the decision below.
LayoutThe map box has a fixed height from the start. Nothing may appear and push content while the person types.
ResetEditing the address or pin clears the confirmation, as built today.
OrderProperty type, Where is it, range card, Photos, More details
UnchangedRange card design, meter, missing chips, footer count, More details, Steps 2 to 4

Decisions for you

1. Switch default: off or on. I drew it off, because a pre-ticked box is weak consent for sharing location. The cost is that most people will not turn it on, so more ranges will use the city only. If you decide the approximate area is low-risk enough to pre-tick, it is a one-word change. This is your call, and for a thesis it is worth writing down which way you chose and why.
2. What the map pin means. Your screenshot shows a map centered on Imus with the street typed as just “w”. The app drew a pin and offered to share it before the address was meaningful. Claude Code should check what the pin is based on and avoid showing “share this area” for a pin that is only the city center.
3. “The confirmation appearing after the fact.” I read this as the map and buttons popping in while you type the street. If you meant the green “Location confirmed” row replacing the form after you press the button, tell me and I will redraw that state so the address stays visible.
