Tenancy setup · simpler (corrected after the audit)

Approved direction, corrected to match what the code and server can do today. Removed: editable dates, a Decline that does not exist, confirmation times, the photo and place line. Added: every state the screen really has.

What changed from v9

  • Dates are read-only. They come from the reservation. The form has two fields only: rent and rent due day (blank, 1 to 28).
  • "Decline" is now "Cancel setup". The server has one cancel, which ends the setup for both people, so a confirmation sheet says so.
  • No "Today" timestamps. The server returns two yes/no flags, not times.
  • Property card is text only, from the property summary the screen already receives. A photo and place need a small read change and are optional.
  • Message appears only if a conversation id is available on this screen. The audit has not verified that.
  • Start stay is offered to either person once the start date is reached. If the renter confirms on or after the start date, the tenancy starts at once.
  • Refresh button removed. The screen reloads when it opens and when the app returns to the foreground, which is what the code already does.
  • Backend: none.
