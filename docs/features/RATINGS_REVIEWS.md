## Review targets and eligibility

Only an active Tier 1 actual participant of an ended tenancy with recorded actual end/ended timestamp no later than the Philippine current date/server time may submit. Reservations and active tenancies do not qualify. Property review: tenant only, property derived from that tenancy. Participant review: either participant reviews the actual other participant, never themselves or an arbitrary supplied user. One review per tenancy/reviewer/kind; multiple real completed tenancies may each generate feedback. No rating defaults, review deadline, payment prerequisite or inferred tenancy completion is introduced.

The existing public.reviews reciprocal table, 1-5 checks, uniqueness and validate_review trigger are reused for participant submissions. Private rentlease_reviews.entries retains immutable original review snapshots and publication metadata; property reviews live there without pretending a property is a user. Legacy valid reciprocal reviews are imported as pending, never automatically approved or counted as property reviews. Legacy records with oversized/inconsistent evidence stay untouched/unpublished and block a duplicate reciprocal submission; their recovery/onboarding needs separate authorized review. No existing review is overwritten or deleted.

## Publication and moderation

New feedback is pending. Independent active Admins can approve/reject pending entries, hide approved feedback and re-review rejected/hidden entries. Administrators cannot moderate feedback from any tenancy in which they were a participant, including property feedback about their own rental. Every decision requires a private note and exact revision, rotates revision/updated/moderated timestamps, and appends immutable history. Rejected/hidden feedback contributes neither a public count/average nor property NLP input. Inconsistent/future completion evidence is excluded from import/approval/publication. The Admin UI shows the latest 20 history entries per row and 20-row queue paging; full history remains stored. Author context shows only the caller's own submission state/text, not internal moderation notes or the counterpart's pending feedback.

Public read RPC returns real approved counts/averages and 20-row pages. It omits reviewer IDs, source tenancy IDs, profiles, legal names, phone fields, verification evidence and internal notes; cards intentionally use protected reviewer identity rather than invented names. Property visibility requires owner, actual tenancy participant or an active/available published listing. User feedback is visible to self, ended-tenancy counterpart or readers of an eligible published landlord; this is not a directory of tenant reputations. Raw public.reviews remains ungranted and has an additive restrictive RPC-only policy; no direct client writes. Existing policies/functions are not replaced. Managed reciprocal source updates/deletes and original private content/bindings are blocked; text/rating editing is outside this phase.
