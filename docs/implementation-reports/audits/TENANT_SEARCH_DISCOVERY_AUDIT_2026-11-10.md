## Confirmed frontend fixes

1. A failing property_photos enrichment query previously rejected an otherwise successful authorized listing search. manualSearchService.search now retains the real parsed text/rent/property rows with null thumbnails. It discards all failed/partial photo URLs, still propagates account/session changes and cancellation, and does not turn a listing-query error into a successful/empty response. SearchListingCard uses the neutral Photo unavailable label. Discover/manual search and recommendation candidate loading benefit through the existing shared service; no new fetch path, query/grant or persistence policy.
2. The legacy Saved Listings fallback incorrectly stated that map results were deferred. It now identifies Saved rentals as unconnected and directs users to the already-existing Nearby rentals GPS map. Existing layout, carousel, navigation and placeholders remain otherwise intact.
